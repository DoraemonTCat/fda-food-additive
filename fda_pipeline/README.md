# FDA Food Additive — แปลงประกาศ สธ. วัตถุเจือปนอาหาร เป็นตาราง

แปลง **บัญชีหมายเลข 1** ท้ายประกาศกระทรวงสาธารณสุข (ฉบับที่ ๔๖๘) พ.ศ. ๒๕๖๘
จาก PDF 839 หน้า เป็นตาราง flat 9 คอลัมน์สำหรับนำเข้าฐานข้อมูล

**ผลลัพธ์ปัจจุบัน:** 74,566 แถว · 391 INS · 234 รหัสหมวดอาหาร

---

## เริ่มใช้งาน

```bash
pip install -r requirements.txt
python pipeline.py
```

ได้ไฟล์ `output/FOOD_ADDITIVE_extracted.xlsx`

ตั้ง path ของ PDF ได้ที่ `config.py` (`PDF_PATH`)

### ตัวเลือกอื่น

```bash
python pipeline.py --pages 2-10          # ทดสอบเฉพาะบางหน้า
python pipeline.py --group-mode group    # กลุ่มสารยุบเป็นแถวเดียว (ดูหัวข้อ "กลุ่มสาร")
python pipeline.py --source easyocr      # ผ่าน OCR service (ดูหัวข้อถัดไป)
```

## คอลัมน์ในไฟล์ผลลัพธ์

| คอลัมน์ | ความหมาย | ที่มาใน PDF |
|---|---|---|
| `INS_NO` | เลข INS ของสาร | บรรทัด `INS:` ในหัวเรื่อง |
| `NAME_FML` | ชื่อสาร (ภาษาอังกฤษ) | ชื่อเรื่องของสาร |
| `FUNCTION` | หน้าที่ของสาร (ภาษาอังกฤษ) | บรรทัด `หน้าที่:` แปลผ่าน `function_map.py` |
| `FA_MAX` | ปริมาณสูงสุดที่อนุญาต (มก./กก.) | คอลัมน์ "ปริมาณสูงสุดที่อนุญาต" |
| `FACTOR_CACULATE` | **ยังไม่ทราบนิยาม** ใส่ `1` ทุกแถว | ไม่มีในเอกสาร |
| `REMARK_REF` | ปีที่รับค่ากำหนด (พ.ศ.) | คอลัมน์ "ปีที่รับค่ากำหนด" |
| `REMARK` | เงื่อนไข | คอลัมน์ "เงื่อนไข" |
| `CODEXNUMBER` | รหัสหมวดอาหาร | คอลัมน์ "รหัสของหมวดอาหาร" |
| `CODEXNM` | ชื่อหมวดอาหาร | คอลัมน์ "หมวดอาหาร" |

**1 แถว = 1 ชุดของ (สาร × หน้าที่ × หมวดอาหาร)**
สารที่มี 2 หน้าที่ และใช้ได้ 64 หมวดอาหาร จะได้ 128 แถว

## เชื่อมต่อ OCR service

โหมด `--source easyocr` ต้องต่อถึง pod `ocr-gateway` ใน namespace `production` ก่อน

**1. เปิด SSH tunnel** (ค้างไว้ อย่าปิด)

```bash
ssh -N k8s-fda-tunnel-new
```

ตั้งค่าใน `~/.ssh/config`:

```
Host k8s-fda-tunnel-new
    HostName 122.8.150.97
    User root
    LocalForward 6443 192.168.0.105:6443
    IdentityFile ~/.ssh/id_ed25519_peeframesave
    IdentitiesOnly yes
    ServerAliveInterval 30
```

**2. port-forward เข้า pod** (ผ่าน Lens หรือ kubectl)

```bash
kubectl -n production port-forward pod/ocr-gateway-xxxxx 8003:8000
```

**3. ตรวจว่าต่อติด**

```bash
curl http://localhost:8003/ocr-service/ping     # ควรได้ "pong"
```

เอกสาร API: <http://localhost:8003/docs>

| Method | Path |
|---|---|
| GET | `/ocr-service/ping` |
| GET | `/ocr-service/get-ocr-support` → `["easyocr","aigen","other"]` |
| POST | `/ocr-service/ocr?ocr_name=<engine>&doc_type=general` (multipart, field `file`) |

ตอบกลับ: `{"metadata": {...}, "data": {"content": "<ข้อความ>"}}`

## ทำไมค่าเริ่มต้นไม่ใช่ OCR

PDF ฉบับนี้ **มี text layer ครบทั้ง 839 หน้า** (1.6 ล้านตัวอักษร ไม่มีหน้าที่เป็นภาพเปล่า)
อ่านตรงๆ ได้ข้อความถูกต้อง 100% พร้อมพิกัด x/y ของทุกคำ ซึ่งจำเป็นต่อการแยกคอลัมน์
เพราะตารางในเอกสาร **ไม่มีเส้นขอบ**

ผลทดสอบ OCR กับหน้า 2 (ภาพ render ใหม่ คมชัด ไม่ใช่ภาพสแกน):

| Engine | ผล | เวลา |
|---|---|---|
| `aigen` | **HTTP 500 ทุกครั้ง** (ทั้งภาพ 1654×2339 และ 650×801 เวลาเท่ากัน ~130 วิ = timeout ตายตัว) | 130 วิ |
| `easyocr` | สำเร็จ แต่คอลัมน์ `FA_MAX` ถูก **7 จาก 20 แถว (35%)** | 40 วิ |

ตัวอย่างที่ `easyocr` อ่านผิด:

```
350  -> 3รก        2000 -> 2dd0       1000 -> 1oo0 / too0 / ioon
800  -> 8o0        500  -> 5dd / 5q0  188  -> lbb / 1b3
110  -> 1lo        XS250 -> /5250     TH1  -> 7}1
2568 -> 2553   <-- ปี พ.ศ. ผิดแต่ยังเป็นปีที่ถูกต้องตามรูปแบบ ตรวจจับไม่ได้
```

และ output เป็น string เส้นเดียวไม่มีขึ้นบรรทัด:

```
...3รก 127,188,7}1 2559 เปรงแคง) 01.3.2 ผลึตภัณฑท์ไซเค็มไนเครื่องตึม 2dd0...
```

จึงแยกกลับเป็น 9 คอลัมน์ไม่ได้ **โหมด OCR ในสคริปต์นี้ทำได้แค่ดึงข้อความดิบเก็บไว้**
(มี cache ราย page รันซ้ำแล้วข้ามหน้าที่ทำแล้ว)

> ข้อมูลกฎหมายที่ปริมาณสารเจือปนผิดไม่ได้ จึงเลือก text layer เป็นค่าเริ่มต้น
> ถ้าจำเป็นต้องใช้ OCR ตามนโยบาย ควรแก้ `aigen` ให้ใช้งานได้ก่อน

## เรื่องที่ต้องรู้ก่อนแก้โค้ด

โครงสร้างเอกสารซับซ้อนกว่าที่เห็น ข้อสมมติที่ดู "ชัดเจน" หลายข้อผิด:

1. **หัวเรื่องเป็น 2 คอลัมน์** ซ้าย = ชื่อ/INS/ชื่ออื่น, ขวา = หน้าที่
   อ่านเป็น text ล้วนจะสลับกันมั่ว ต้องแยกด้วยพิกัด x
2. **เส้นแบ่ง 2 คอลัมน์ไม่คงที่** บางหน้า `หน้าที่:` อยู่ x=303 บางหน้า x=319
   จึงต้องหาเส้นแบ่งจากตำแหน่งคำว่า `หน้าที่:` เองทุกบรรทัด
3. **สารตัวใหม่เริ่มกลางหน้าได้** ใต้ตารางของสารตัวก่อน
   จึงอ่านหน้าแบบ "ส่วนหัว + ส่วนตาราง" ไม่ได้ ต้องไล่ block จากบนลงล่าง
4. **จัดบรรทัดด้วย `round(top/4)` ไม่ได้** คำในบรรทัดเดียวกันต่าง y ได้ถึง ~0.7pt
   แล้วตกคนละช่องปัดเศษ (`INS:` y=473.38 กับค่า `160c(ii)` y=474.10)
   ต้องจัดกลุ่มแบบไล่ลำดับ
5. **ฟอนต์ทำให้สระ/วรรณยุกต์เพี้ยน** เช่น `อิมัลซิไฟเออร,์` (วรรณยุกต์หลังจุลภาค)
   `function_map.py` จึงเทียบแบบตัดสระ/วรรณยุกต์ออกก่อน
6. **`INS: -`** มีจริง หมายถึงสารที่ไม่มีเลข INS (เช่น MALTITOL SYRUP, PAPAIN)
   ต้องจับให้ได้ ไม่งั้นจะเสีย `หน้าที่:` ของสารนั้นไปด้วย

## กลุ่มสาร

สารบางกลุ่ม เช่น **PHOSPHATES (กลุ่มฟอสเฟต)** มี INS หลายสิบตัว
แต่ละตัวมีชื่อและหน้าที่ของตัวเอง **แต่ใช้ตารางหมวดอาหารร่วมกันชุดเดียว**

```
หน้า 480-484  PHOSPHATES (กลุ่มฟอสเฟต)
              INS: 338, 339(i), 340(i), ... รวม 30 ตัว
หน้า 485+     ตารางหมวดอาหารชุดเดียว ใช้กับทั้ง 30 ตัว
```

ค่าเริ่มต้น (`--group-mode expand`) แตกเป็นราย INS — กลุ่มนี้กลุ่มเดียวได้ 13,041 แถว

> **ยังไม่ได้รับการยืนยันว่าถูกต้องตามที่ต้องการ** ถ้าปลายทางอยากเก็บเป็นกลุ่ม
> ให้ใช้ `--group-mode group`

## ข้อจำกัดที่ทราบ

| เรื่อง | สถานะ |
|---|---|
| `FACTOR_CACULATE` | ใส่ `1` ทุกแถว **ยังไม่ทราบนิยาม** |
| กลุ่มสาร | ยังไม่ยืนยันว่าต้อง expand หรือ group |
| `FUNCTION` 4 คำ | ยังเป็นภาษาไทยในไฟล์ผลลัพธ์ (ฟอนต์ทำสระเพี้ยน) |
| ตาราง `FUNCTION` ไทย→อังกฤษ | อิง Codex GSFA Table 3 **ยังไม่มีใครตรวจ** 4 คำมี `NEEDS_REVIEW` |
| `FA_MAX` ผิดรูป | 8 แถว จาก 74,566 (0.011%) — ชื่อสารยาวทะลักเข้าคอลัมน์ |
| `REMARK_REF` ผิดรูป | 6 แถว |
| คำเตือนตอนรัน | 2 จุด (หน้า 22-23) |
| โหมด OCR | ได้ข้อความดิบเท่านั้น ยังไม่แปลงเป็นตาราง |

`REMARK` ว่าง 50% เป็นเรื่องปกติ — เอกสารไม่ได้ระบุเงื่อนไขทุกแถว

## คำถามที่ยังไม่มีคำตอบ

1. `FACTOR_CACULATE` คืออะไร คำนวณจากอะไร
2. กลุ่มสาร (PHOSPHATES) ปลายทางต้องการแบบ expand หรือ group
3. มีตาราง mapping `FUNCTION` ไทย→อังกฤษ ฉบับทางการของทีมอยู่แล้วหรือไม่
4. มีไฟล์ผลลัพธ์ฉบับเดิมให้เทียบผลหรือไม่
5. `aigen` ขึ้น 500 ทุกครั้ง — เป็น bug ของ service หรือใช้ผิดวิธี
